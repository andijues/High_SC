# 省额度优化与验证边界

1.2.0 保留用户选择的模型与推理强度。本机实际验收使用 `gpt-6.1-sol` / `xhigh`，没有切换到低强度或其他模型。中文译文、三项逐段批注、原文高亮、全文骨架和离线排版均保留。

## 四项优化

### 同一论文跨导入复用

缓存位于数据目录的 `cache/`，与项目源代码和 EXE 分开保存。键同时覆盖原始 PDF、解析内容、模型、推理强度、渠道与认证作用域、上下文设置和分析版本。凭据只参与不可逆指纹计算，不写进缓存。

同一 PDF 在新任务中再次导入时，程序可复用已校验的全文骨架、段落和图表说明；完整命中无需请求模型。模型、渠道、分析版本等变化会产生独立缓存。缓存损坏时重新生成，不能通过校验的段落不会进入成品。

缓存保存模型原始生成结果；人工修改留在原任务，不会被其他任务的缓存覆盖，也不自动传播为新的模型结果。明确要求单段重做或完整重做时会绕过相应缓存。

旧版已完成的任务仍可直接导出。由于旧版没有完整记录模型/提示词身份，升级不会把来源不明确的历史结果自动标记成新版缓存；跨导入复用从有新版身份记录的任务开始。请保留 `cache/`，它用于节省后续调用，不属于构建垃圾。

### 仅补做失败段落

一批响应中，合格段落先写入任务与缓存。缺失、重复编号或字段不完整的段落会定向补做，最多进行有限次修复；持续失败时保留已完成内容，供后续继续。JSON 完全损坏、无法解析时只能缩小尚未完成的批次，不能假装已经取得未返回的内容。

### 自适应合批

默认开启自动合批，按原文长度、章节边界和普通 API 的输出预算安排每批 1–8 段。超长段落独立处理，文本不截断、不改为摘要。无效或截断响应会缩小批次恢复。

在模型高级设置中关闭“自动合批”后，使用“手动每批段落数”。Codex 自己管理输出预算；自动模式超过 4 段时按批量将 Codex 超时最多放宽至当前值的两倍（不超过 1,800 秒），避免较大的 xhigh 请求被过早停止。超时或截断后会降低后续批量上限。普通 API 会根据配置及额外参数中的输出上限保守缩小批次。

### 按章节减少重复上下文

全文分析仍覆盖全部正文。后续每批保留核心主张、完整五阶段论证链、证据边界、强弱点评和完整术语表，只省略不相关章节的角色说明；保留当前及相邻章节。摘要、讨论、结论和明确跨章节引用使用完整骨架。

目标段落原文完整发送。前后邻段以及不连续补做目标之间的必要邻段作为只读参考发送，避免因定向修复丢失局部指代关系。图表说明同样只在能够确定关联段落时缩减章节上下文。

## 如何观察效果

进度页显示本轮模型请求数、缓存复用段落数与定向补做数量。任务 JSON 的 `optimization` 还记录批量大小、业务输入字符数及省略的重复骨架字符数。

这些字符统计不包括 Codex 内部系统指令，不是计费 tokens。若接口提供缓存输入和推理输出，程序分别记录到 `tokens.cached_input` 和 `tokens.reasoning_output`；它们分别属于输入和输出总量，不应重复相加。订阅额度不能仅用这些数值精确换算。

## 验证

- 自动化测试覆盖精确缓存命中、模型/强度/版本隔离、损坏缓存、人工修改保护、图表路径、不连续补做上下文和失败恢复。
- 24 段本地模拟对照：固定 4 段和完整骨架为 6 次请求，自动合批与相关章节骨架为 3 次；业务输入字符为 43,038 → 15,003，模拟批注字段一致。该数字不是实测订阅额度降幅。
- 真实 Codex 验收：用已有论文的 6 段与已有译文作对照，仅发起 1 次 `gpt-6.1-sol / xhigh` 请求，完成完整翻译和批注，未发现关键内容、数值和引文遗漏。不会将这次小样本结论扩展成所有论文的质量等同保证。
- Windows EXE 测试覆盖真实目录窗口、完整模拟生成、同一 PDF 再导入零模型请求、重启持久化及托盘。

完整翻译和详细论证分析仍然需要模型处理。实际等待时间和额度节省取决于论文结构、输出长度、缓存命中和服务端行为；首次处理新论文不会获得重复论文的完整缓存收益。
